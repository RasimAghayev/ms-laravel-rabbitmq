## Resolved while adding the Phase 4 CI gate

- **CVE-2026-45070** (symfony/mime, medium severity, email header injection via non-token characters in MIME parameter names) was flagged by `composer audit` the moment that gate was turned on, in both `admin` and `main` — the installed `symfony/mime` v8.1.7 fell inside the affected `>=8.1.0,<8.1.10` range. Fixed with a minimal, non-breaking lockfile bump (`composer update symfony/mime --with-all-dependencies`, both already-permitted by `laravel/framework`'s and `symfony/mailer`'s existing `^8.0.0` constraint — no `composer.json` change). `composer audit` is clean in both apps after the bump; this is not one of the 7 already-tracked dependency-bot PRs (item #4 above), since the CVE was reported 2026-10-28, after those PRs were opened.

## Not treated as debt

- The same-class-name, two-implementations sync pattern (`App\Jobs\ProductCreated` etc.) is a deliberate, working design, not an accident — see `docs/ARCHITECTURE.md`. It's fragile to independent refactors (the two apps must keep the class names and constructor shapes in sync by convention, with nothing enforcing it), but that's an inherent property of the chosen pattern, not a bug to fix.
- `main_app`'s lack of product-specific HTTP routes is intentional per the README (`main` is the read side; this audit found no indication a read API was ever planned to land here).
